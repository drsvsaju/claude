# Native control audit (v1.20 → v2.0)

Source: `index.html` on `focus-app` (23,029 lines; CSS 9–3793, markup 3795–4916, script 4916–23027). Read-only audit, no code changed.
Every line number is paired with an id or function name because lines drift once editing starts.
"Static" = in the HTML markup. "JS" = inside a template string, so the control is re-created on every render of that function.
Single-quoted and unquoted attribute variants (`type='…'`, `type=date`, `title='…'`) were searched too: **0 hits** for all of them. There is no untyped `<input>` (every one has `type=`).

## The existing custom pieces

### Confirm dialog: `#confirmDlg` (4627–4632) and `confirmDlg()` (22191–22204)

- Signature: `confirmDlg({ title, body = '', ok = 'OK', danger = false, type = '' })` → `Promise<boolean>`.
- `title` and `body` are written with `textContent` (plain text only). `ok` is the confirm label; `danger` switches the button class between `btn danger` and `btn primary`. The cancel label is fixed ("Cancel").
- `type`: shows `#cfType` with the placeholder `Type ${type} to confirm` and keeps OK disabled until the trimmed, upper-cased input equals `type`.
- Resolves `true` on OK, `false` on Cancel or Esc (`dlg.oncancel`). No backdrop close. No Enter handling in `#cfType`.
- Handlers are assigned as properties (`onclick`, `oncancel`, `oninput`) and cleared in `done`. It is **one shared dialog and not re-entrant**: a second call while it is open replaces the handlers and the first promise never settles.
- Missing for v2: single-button (alert) mode, custom cancel label, rich body, an icon or Pomeo, a default-focus rule for destructive actions, a queue.
- Call sites: **12** (21267, 21776, 21777, 22242, 22244, 22253, 22263, 22264, 22280, 22320, 22362, 22364), all in live-session and clan code. `type` is used once (clan disband, 22364, with `CLAN.doc.tag`).

### Toasts: `toast()` 5077, `toastUndo()` 16120, host `#toast` (4890)

- `toast(msg, ms = 2600, ok = false, opt = {})` → `undefined`.
  - `ok = true` prepends `CHECK_SVG`. The message is a text node (no HTML).
  - `opt.now`: skip the focus hold. Without it, a toast that the user did not just trigger (`userJustActed`, 1.5 s window, 19791) is queued until the focus block ends (`holdForFocus('toast', 't:' + msg, …)`, 19797).
  - `opt.log === false`: do not copy the toast into the inbox. `opt.type`, `opt.go`, `opt.key`, `opt.read` are passed to `inboxLog` 16165.
  - A toast with the same visible text as one on screen is dropped. At most three are visible; the oldest is dismissed.
  - `toastHost()` 5072 moves `#toast` into the top-most open `<dialog>` so it is not inert, or back to `<body>`.
  - Classes `.toast-item` → `.in` → `.out` (240 ms); siblings glide with `glideToasts` 5100 at Full motion.
- `toastUndo(msg, undo, ms = 5000)`: adds a `button.undo`; on click runs `undo()` and shows "Restored". Not held for focus, not de-duplicated, always logged.
- `dismissToast(el)` 5094.
- Call sites: **253** for `toast` (255 textual hits including the definition and its own deferred call at 5079; 105 pass `ok = true`), **19** for `toastUndo`.
- Missing for v2: variants (error / warning), a generic action button, manual close, a pause on hover.

1. **`#authUser`, `#authPass`, `#authPass2` (3896, 3901, 3910).** Password managers and autofill depend on real inputs with `autocomplete` and a real `form` submit; the Show / Hide button flips `input.type` (18615). Restyle only.

5. **`#cmdInput` (4775).** Already a proper ARIA combobox; reuse its pattern rather than replace it.

7. **Native inputs as hidden value carriers inside custom controls.** For Switch, day chips, subtask ticks and radio cards, keep a visually hidden `input[type=checkbox|radio]` with the same id / name / `data-*`. `.checked`, bubbling `change`, `:has(input:checked)`, the row-toggle code and the on/off sounds keep working, and 69 `.checked` reads / writes need no change. ## Riskiest swaps

1. **`#presetSelect` → Combobox (4141).** `renderSessionInputs` 6911 replaces its options by `innerHTML` on every `renderAll()` (25 call sites, including cloud snapshots that arrive at any time): an open popup or a focused option is destroyed mid-interaction unless the component re-renders its list in place. The selection is never set through `.value`, only through that re-render. The shortcut guard (15461) ignores keys only inside `input, select, textarea`, so a focused combobox button would let `1–9`, `S`, `R`, `P`, `N` and Space act on the timer. `label[for="presetSelect"]` needs a labelable target. No test touches this control. The favourites / recents rows have no data behind them yet.
2. **Native `confirm()` ×8 and `alert()` ×1 → ConfirmDialog.** Blocking calls become promises: `buyItem` 8524, `clearRecents` 6759 (returns a boolean) and the `[data-remove]` branch at 18829 are synchronous. `buyItem` needs a busy guard against double clicks. `confirmDlg` is a single shared dialog and not re-entrant, and `handleInvite` 9996 fires during startup next to the tutorial, daily-reward and migrate dialogs. There is no single-button mode for the `alert`. In `tests/`, 39 files answer native dialogs with `page.on('dialog')` and 8 stub `window.confirm`.
3. **Settings checkboxes → Switch (25 rows, plus 16 elsewhere).** The row-toggle code (18753–18762) marks a row clickable only if it holds exactly one `input[type="checkbox"]` and no `select, button, a`; a `<button role="switch">` fails both tests. The on/off sound listener checks `el.type === 'checkbox'` (15925). `#setPosts` and `[data-posttype]` are handled by a **document-level** `change` listener (9899), so the event must bubble that far with `e.target.id` and `.checked` intact. `PV_BLOCK` stops demo changes by cancelling the `click` in the capture phase (17672); a custom switch that toggles on `pointerup` or `keydown` slips past it. `previewLockSettings` 17685 disables `#tab-settings input, select, .setting button`. `renderSettings` writes `.checked` on 25 ids and reads `$('#setTod').checked` back (7273).
4. **`#sessPreset` and the host-sheet radios (21643–21660).** The sheet re-renders `#hsBody.innerHTML` on every step and on its own `change` events (21705–21706), then calls `$('#sessPreset').focus()` or re-focuses a radio by `input[name=sessWhen][value=…]`. Components must re-initialise after each render and expose `.focus()` on the id. `hostSheetRead` 21668 reads `input[name]:checked`; CSS uses `.hs-opt:has(input:checked)`; first-focus logic queries `.hs-step.on input` (21683). Changing `#sessPreset` also changes the timer's preset and calls `renderAll()` underneath the open modal.
5. **`#sessTime` → TimePicker (21659).** It sits inside the `<label>` of the "Plan it for later" radio. Any click inside a custom picker placed there toggles the radio, fires the delegated `change`, re-draws the sheet and destroys the picker. Validation is the regex `/^\d\d:\d\d$/` (21718): a 12-hour display must still store 24-hour `HH:MM`.
6. **Date inputs → DatePicker (`#csdDate`, `#tdDue`, `#remDate`, `#examDate`, `#tutExamDate`).** Callers get and set `.value` as `'YYYY-MM-DD'` on the same id, with `''` for empty; `#examDate.min` is set as a property (12992). `#csdDate` is parsed with `split('-')` and no validation (22340). All five live inside modal dialogs: a popover appended to `<body>` renders under the top layer and is inert, and under Glossed Interface `dialog` and `.card` have `backdrop-filter`, which makes them the containing block for `position: fixed`. Tests `fill()` these ids (`#remDate` in 3 files).
7. **`#presetForm` number inputs → NumberStepper (4834–4837).** This is the only form that relies on native constraint validation (no `novalidate`): `required`, `min` and `max` (assigned as properties from `PRESET_LIMITS` at 18980) show browser bubbles and block submit. With custom steppers those messages vanish and the submit handler silently clamps (241 becomes 240, empty becomes the minimum). Enter-to-submit from a number field must survive. The `'Untitled preset'` fallback (18985) becomes reachable.
8. **`#setMotion`, `#setGlass` and the other Settings selects.** `#setMotion` reads `e.target.selectedOptions[0].textContent` (18783), the only native-select API in the file. `#setGlass` is disabled through `.disabled` (7280) and has its value re-set from `setGlass()` (11422). `goSetting` 16324 focuses the row's first `input, select, button`; `filterSettings` 16300 and `cmdList` parse the row's DOM shape. Tests call `selectOption()` 17 times in 8 files (`#setMotion` ×3, `#csdName` ×3, `#uisPack` ×2, `#setGlass` ×2, `#remRepeat` ×2, `#setPomeoTalk`, `#remPreset`, `#csdPattern`, `#ccDesc`).
9. **Range → Slider (`#setAmbVol`, `#uisVol`, `#shopAmbVol`).** `#uisVol` gives `input` and `change` different jobs (store vs play a sample, 15958–15959). `setAmbientVolume` saves on every `input`. The phone gesture guards exempt only `input, textarea, select, button…` (`NO_SWIPE` 16546, pull-to-refresh 16517): a div-based thumb dragged sideways switches tabs unless it carries `[data-noswipe]`. `#shopAmbVol` is re-created by `renderShop` when a cloud snapshot triggers `renderAll` mid-drag.
