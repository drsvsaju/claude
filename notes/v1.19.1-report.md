# Pomodorolist v1.19.1 — report (leaderboard fix, no Monthly board, rank next to your name)

Built on top of v1.19 in `v1.19.1: …` commits on `focus-app`.

**No Firebase console steps are needed.** No rules or indexes changed. If v1.19 isn't live yet, deploy v1.19.1 the same
way (its rules and indexes are the v1.19 ones). If v1.19 is already live, upload only `index.html`.

## 1. Bug: "Focus time" opened the Ranks board
**What you saw:** after a visit to Ranks (or Streaks), clicking **Focus time** stayed on the Ranks "This season" board,
or jumped back to it. A reload didn't help.

**The cause.** Each board button reopens the last period you used on that board. The app remembers one period per board:
`lbFocusPeriod`, `lbGardenPeriod`, `lbRankPeriod`, `lbStreakPeriod`.
- The render function filed the period correctly under all four boards.
- The click handler was written when there were only two boards (v1.16). It kept only two cases: garden periods went to
  Garden, and everything else went to Focus.
- So clicking **Ranks** stored `season` as the Focus period, and clicking **Streaks** stored `streak`. The Focus time button
  is drawn as `data-period="<the Focus period>"`, so it then carried `season` and opened Ranks.
- The bad value is part of the saved UI state, so it survived a reload.
- I reproduced it on the v1.19 build, clicking Ranks, then Focus time, then reloading and clicking Focus time again. Each
  time the result was still Ranks · This season, and the Focus button held `season`. The fixed build opens Focus time ·
  Weekly in both cases.

This is the same family as the v1.18 Friends switcher bug: a switcher's state written by two code paths that disagree.

**The fix.**
- One function (`setBoardPeriod`) now files a period under its own board, and both the click handler and the render
  use it.
- A board button now says which board it opens (`data-kind`). The handler reads that board's remembered period when
  clicked, instead of trusting a value baked into the button.
- A remembered period counts only if it belongs to that board. Saved state that 1.19 corrupted (for example `season`
  stored as the Focus period) is repaired on read, so users who already hit the bug are fixed automatically.
- An unknown saved scope or clan-board period falls back to the default.

**Other switchers checked.** I looked at every other switcher in the app (14), both in the code and with a click-through
test:
- Stats, Friends · Study sessions · Challenges, Reminders · To-do · Flashcards, Boss · Questline, the Garden views,
  achievement categories, the inbox filter, and the Collection log filter;
- also the clan board period, the clan shop tabs, the to-do priority, the share-card size, the auth tabs and the session
  mode.

Each one stores a single value and has a single writer, so none has this bug. I also checked every class toggle in the
app that might receive an undefined value, the cause of the v1.18 bug; all of them receive true/false.

## 2. The Monthly focus board is gone
- Focus time now has **Daily · Weekly · Lifetime**. The Ranks board (this season = this UTC month) replaces Monthly.
- If a user's saved view was Monthly, they get **Weekly** instead of a broken board. Both the open board and the Focus
  button's remembered period are repaired.
- **`monthKey` / `monthMin` are still published to `publicStats`**, and the stats charts' Month view is unchanged. Older
  app versions still on someone's phone keep their Monthly board.
- Rules and indexes: **unchanged**. The `publicStats` index on `global · monthKey · monthMin` is now used only by older
  app versions. Leave it in place; it costs nothing.

## 3. Your rank next to your name
**Header (top right, next to the level).**
- From 481 px wide there's a small chip with the rank gem and its name (e.g. "Gold II"), in the same style as the level
  chip. Tapping it opens **Leaderboard → Ranks**.
- On phones (480 px and narrower) the chip doesn't fit beside the header buttons. The gem sits **inside the level chip**
  instead: tapping the gem opens the Ranks board, and tapping the rest of the chip still opens the profile. The rank's
  name is in the gem's label for screen readers.
- To make room, up to 600 px the header shows the tomato logo without the word "Pomodorolist". On phones of 400 px and
  narrower the seasonal emoji next to the logo is also hidden.

**Player card (Profile tab).**
- The rank badge (gem + name) sits next to your @name, in both the collapsed and the expanded card.
- It is drawn in the card's own colours, so it suits every card style.
- Tapping it scrolls to the **Rank card**, which shows your progress to the next step, and briefly outlines it.
- The Customise preview shows it too, as a label rather than a button.

**Where it doesn't show.**
- True Minimalist hides it, like every rank badge.
- Guests see Bronze III. Their chip opens the Rank card, because guests have no leaderboards.
- The demo shows its sample rank, and the chip opens the demo Ranks board. Nothing is written.
