# Pomodorolist v1.19 — final report (Ranks + Streak leaderboard)

v1.19 is built on top of v1.18 in separate `v1.19: …` commits on `focus-app`. **v1.18 stays deployable on its own**
(live-branch commit `844f9fa`, deploy steps in `notes/v1.18-report.md`). **Deploy v1.18 first**, check it, then v1.19
with the steps below.

## What's new (for users)
- **Ranks, one season per month.** Your counted focus hours this month take you from Bronze through Silver, Gold,
  Platinum and Diamond (three divisions each: III → II → I) to Master and Grandmaster.
- **A head start each new season** from last season's best rank.
- **Season rewards.** The end of a season pays coins and puts a season badge ("Nov 2026 · Diamond III") on the trophy
  shelf.
- **First-time rewards.** The first time you reach a rank you get a cosmetic:
  - Silver and Gold: a frame;
  - Platinum and Diamond: an aura;
  - Master: a poster for Pomeo's room;
  - Grandmaster: an animated frame.
- **Rank-ups mid-block.** A small toast during the focus block, then the full celebration after it ends.
- **Rank badges next to names.** On leaderboard rows and the podium, friend rows, study-session lists and tables, clan
  members and challenge cards. Hidden in True Minimalist.
- **Where you see your rank.**
  - Timer: a compact rank line with a progress bar.
  - Profile: a Rank card with the season, days left, your next step, your placement, last season and the first-time
    rewards.
- **New leaderboards.**
  - **Ranks:** this season's hours.
  - **Streaks:** Current or Best, with the milestone flame.
  - Both have Friends and Global views. A streak that has lapsed drops off the Current board.
- **Demo.** The preview shows all of this with sample data and still writes nothing.

## The numbers
| Rank | Season hours | Divisions (minutes) |
|---|---|---|
| Bronze | 0–10 | III 0 · II 200 · I 400 |
| Silver | 10–25 | III 600 · II 900 · I 1,200 |
| Gold | 25–50 | III 1,500 · II 2,000 · I 2,500 |
| Platinum | 50–80 | III 3,000 · II 3,600 · I 4,200 |
| Diamond | 80–120 | III 4,800 · II 5,600 · I 6,400 |
| Master | 120–180 | — (7,200) |
| Grandmaster | 180+ | — (10,800) |

**I kept the brief's thresholds.**

| Daily study | Diamond (80 h) | Grandmaster (180 h) |
|---|---|---|
| 3 h | about day 27 | — |
| 6 h | — | on day 30 |

- Grandmaster stays rare: a 30-day month at 6 h a day, every day.
- A serious student always has a division within 3–7 hours.
- Lower thresholds would put most 4–6 h students at Master by mid-month, with nothing left to chase.

**What counts.**
- Only completed focus blocks from the session log count, Finish-early blocks included.
- Minutes are grouped by the UTC day the block ended.
- Each UTC day is capped at **14 h (840 min)**.

**Season = UTC month.** The rules can only check the server clock, so the season key must be the UTC month. In India
a season turns over at **05:30 on the 1st**. The first season is **November 2026**, so there are no rewards for earlier
months.

**Placement (soft reset).**
- Your shown rank is the higher of (rank from this season's hours, floor from last season's peak).
- Floors from last season's peak:

  | Last season's peak | Starts at |
  |---|---|
  | Gold | Bronze I |
  | Platinum | Silver III |
  | Diamond | Silver I |
  | Master | Gold III |
  | Grandmaster | Gold II |
  | Bronze / Silver | no floor |

- The floor lifts only the badge. The Ranks board sorts by this season's hours.

**Season reward (coins).**

| Bronze | Silver | Gold | Platinum | Diamond | Master | Grandmaster |
|---|---|---|---|---|---|---|
| 10 | 40 | 80 | 150 | 250 | 400 | 600 |

- Claimed automatically in the next season, once.
- If two devices claim different peaks, only the highest pays, so it never pays twice.

## New Firestore fields
**`publicStats`: no new fields.** The brief asked for `streak`/`bestStreak` on `publicStats`, and the first build put
the season and streak numbers there. That document's update rule then went over Firestore's limit of 1,000 rule
expressions per request, so the write was refused.

The numbers now live in a small new collection, **`rankStats/{uid}`**. Its fields are all optional for old users; an
app before 1.19 simply has no document and shows no badge.

| Field | Type | Meaning |
|---|---|---|
| `username`, `level`, `tier`, `frame`, `color`, `avatar`, `aura` | as in `publicStats` | the look of a board row |
| `global` | bool | shown on the Global boards (the existing "Show me on the global leaderboard" setting) |
| `seasonKey` | string `YYYY-MM` | the current UTC month |
| `seasonMin` | int | counted minutes this season |
| `prevPeak` | int 0–16 | last season's peak rank (sets the placement floor) |
| `streak` | int | current streak (days) |
| `bestStreak` | int | best streak ever |
| `streakDay` | string `YYYY-MM-DD` | the last day the daily goal was met (readers use it to tell a live streak) |
| `joined` | int (ms) | when the account was created (Firebase Auth metadata) |
| `updatedAt` | timestamp | the server time of the write |

Other notes:
- `publicStats` is back to its v1.18 fields. Its rule was also made cheaper: it computes the time allowance once and
  checks only the changed keys on update. The meaning is unchanged.
- `publicProfiles` is unchanged.
- "Erase all data" also deletes `rankStats`.

## New composite indexes (all on `rankStats`, query scope Collection)
1. `global` Ascending · `seasonKey` Ascending · `seasonMin` Descending: the global Ranks board.
2. `global` Ascending · `streakDay` Ascending · `streak` Descending: the global Current-streak board. It asks only for
   live streaks (`streakDay` = yesterday, today, or ±1 day for time zones), so lapsed streaks can't fill its top 50.
3. `global` Ascending · `bestStreak` Descending: the global Best-streak board.

The Friends boards read each friend's document and need no index.

## Updated `firestore.rules` (summary; the full file is at the end)
**`match /rankStats/{uid}`**
- **get:** yourself, a friend, or anyone when `global == true`, unless blocked.
- **list:** only `global == true` documents.
- **create / update / delete:** the owner only.

**Create**
- A valid document (`validRankStats`).
- `prevPeak == 0`.
- `seasonMin ≤ 240`: deleting and re-creating the document can't jump the season.

**Every write (`validRankStats`)**
- Only the fields above.
- `username` is your registered name.
- The look fields are bounded.
- `updatedAt == request.time`.

**Season (`validSeason` / `seasonGrows`)**
- `seasonKey` must be the current UTC month.
- `seasonMin` is a whole number, `0 ≤ seasonMin ≤ 840 × UTC day of the month`.
- Within a season, it never goes down and grows by at most (minutes since the last write + 240).
- `prevPeak` stays fixed within a season.
- At a new season:
  - `seasonMin` starts within the same allowance;
  - `prevPeak` can't be higher than the rank of the minutes the document held.

**Streak (`validStreak` / `streakGrows`)**
- Whole numbers, with `bestStreak ≥ streak`.
- `bestStreak ≤ days since joined + 2`.
- `joined` is in the past and never changes once published.
- The best never goes down and grows by at most (elapsed days + 2) per write.
- `streakDay` is a real date at most one day ahead of the server. The check now handles month ends, which also fixes
  the other day-key checks on the last day of a month.

**What the rules can't fully verify (no server code)**
- **The minutes themselves.**
  - Rules bound how fast `seasonMin` can grow (real time + 4 h, and 14 h × the day of the month) but can't see the
    focus blocks.
  - Worst case: a tampered client adds about 4 h per write beyond real time, still capped at 14 h a day.
  - A new document starts at ≤ 4 h.
- **`prevPeak` at a season change.** It is bounded by what the document held last season, which was itself bounded.
- **Streaks.**
  - `joined` comes from the client (rules can't read Firebase Auth's creation time), and the first publish is bounded
    only by that.
  - A tampered client can claim an old join date once and then grow its best streak by at most a day or two per day.
  - The current streak may jump up to the best, because an honest device that was offline catches up.
- **A live streak** is judged on read from `streakDay`.
  - A streak shows when its last goal day is today, yesterday, or one day earlier in the viewer's calendar. The
    extra day covers time zones: a friend in another country can be a day behind.
  - So someone who missed yesterday in the same time zone can show for at most one more day.
- **Fixing these properly** needs a Cloud Function that recomputes rank and streak from the session log.

## Deploy steps (in this order, after v1.18 is live)
**1. Publish the rules** (Firebase console, project **pomodorolist-bbaa6**)
- Firestore Database → **Rules** → select all, paste the whole `firestore.rules` below (or from `focus-app` on
  `drsvsaju/claude`) → **Publish**.
- This is safe for the live v1.18 app: it adds the `rankStats` collection. The fields v1.18 writes to `publicStats` and
  `publicProfiles` are unchanged in v1.19, and the regression suite runs them against these rules.

**2. Create the three indexes**
- Firestore Database → **Indexes** → **Composite** → **Create index**, three times:

  | # | Collection ID | Field 1 | Field 2 | Field 3 |
  |---|---|---|---|---|
  | 1 | `rankStats` | `global` Ascending | `seasonKey` Ascending | `seasonMin` Descending |
  | 2 | `rankStats` | `global` Ascending | `streakDay` Ascending | `streak` Descending |
  | 3 | `rankStats` | `global` Ascending | `bestStreak` Descending | — |

  Query scope: **Collection** for all three.
- Wait until all three rows say **Enabled** instead of Building… (a few minutes on a new collection; refresh the
  page).
- Without them, the global Ranks and Streaks boards say "This leaderboard needs a Firestore index", and nothing else
  breaks.

**3. Upload the files**
- The v1.19 commit for the live branch is prepared on top of the v1.18 one. See "The v1.19 commit for the live branch"
  below.
- **GitHub website:** `siverieg/Pomodorolist-V1.0` → **Add file → Upload files** → `index.html`, `firestore.rules`,
  `firestore.indexes.json` from `focus-app` on `drsvsaju/claude` (open each → **Download raw file**) → commit message
  `v1.19` → **Commit directly to the main branch**.
- **Git:** `git pull /path/to/pomodorolist-v1.19.bundle main && git push origin main`. The bundle is in `deploy/` on
  `focus-app` and needs the v1.18 commit already on `main`.
- GitHub Pages republishes in 1–2 minutes.

**4. Two-minute smoke test** (hard refresh: Ctrl/Cmd + Shift + R)
1. What's new says **1.19**.
2. **Preview the app.**
   - Leaderboard → **Ranks** shows the sample friends with badges.
   - **Streaks → Current** has no Justin; **Best** has him.
   - Exit preview.
3. Log in.
   - Timer: a rank line ("Bronze III · … this season").
   - Profile: the Rank card.
4. Leaderboard → **Ranks → Global**, then **Streaks → Current/Best → Global**: they load, with no "needs a Firestore
   index" message.
5. Firebase console → Firestore → Data: a `rankStats` document with your uid is there after you open the app or finish a
   focus block.
